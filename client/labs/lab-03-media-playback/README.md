# LAB-03/v2 — bounded inbox audio/sketch playback

Independent ESP-IDF BOX-3 experiment. This is a lab candidate with **provisional lab criteria**, not approved product behavior or budgets. Product firmware and LAB-02 are unchanged.

`make lab.lab03.build KIT=<kit>` builds manual; `make lab.lab03.scripted KIT=<kit>` runs the stage-driven sequence followed by 600 seconds of repeated playback. Default capture is 780 seconds. `make lab.lab03 KIT=<kit>` permits manual Next / Play / Pause / Stop / Out. Private deployment credentials enter a mode-0600 ignored build overlay. `LAB03_CLIENT_ADDRESS` selects the host LAN IPv4 when route discovery is unsuitable. Server port is fixed at 8766. Standalone builds without KIT compile with empty credentials and cannot run network scenarios. Standard `idf.py -C client/labs/lab-03-media-playback build` is also supported after configuring private network settings.

For persistent manual playback, start the fixture server in a separate terminal with `make lab.lab03.server`; it listens on `0.0.0.0:8766` until interrupted. The flashed image must have `LAB03_SERVER_URL` set to this host's current LAN address, which is normally injected by `make lab.lab03.build KIT=<kit>`.

Boot proof: fresh `LAB03_READY build=<24 hex> fixture=lab03-media/v1 harness=0|1 trace_schema=lab03-trace/v1` after capture is armed and reset. Shared runner adapter `lab03` creates v2 manifest/events, owns the server process, checks its run/fixture identity, builds from frozen private defaults, revalidates the USB kit before flash, and preserves partial evidence. Run identity is host runtime context; firmware fingerprint excludes run ID and kit nickname. The compiled ID lives in a generated build-directory header to keep compiled identity separate from SDK configuration. A frozen sidecar restores that header after fresh-build directory preparation. Standalone IDF builds fall back to the configured standalone ID. Host received timestamps correlate device clock and service clock; they do not establish a precise acoustic/LCD clock mapping.

## Foundation and ownership

LAB-02's `inbox_model.c`, `inbox_model.h`, and geometry limits are compiled directly, unchanged. Its card-view/pool implementations depend on LAB-02 session snapshots, delayed-bind traces, and paging intents; importing that component would start a second session owner. LAB-03 instead adapts its retained binding approach to three persistent card roots with one image. It uses its own media operation generation and session identity. The LAB-02 Wi-Fi lifecycle is copied with a LAB-03 namespace. Nothing is promoted into `client/shared/`.

LVGL callbacks/timer own focus, page application, labels and pixels. The media worker owns bounded fetch, validation, codec writes and raster. The page worker prepares a bounded inbox page independently of audio. Publication uses a nonblocking UI try-lock and a worker wait of at most 2ms; workers never retain widgets. New play, stop and sign-out invalidate generation immediately; each accepted queued play drains to one worker terminal including cancellation before worker start. Queue-full intents are rejected explicitly. Focus alone preserves playback; pause preserves one worker raster plus a published and displayed copy, including while offscreen. A late result cannot mutate a current generation. No cache, retries or seek are implemented.

## Fixed inputs and proposed envelope

The paired service is `server/labs/lab-03-media/server.py`; comparison authority is its checked-in `fixtures/manifest.json` (lab03-media/v1). A=12-stroke short sketch, B=4096-stroke maximum accepted dense sketch, C=audio-only, D=fixed 503, E=slow audio, F=slow sketch. Each stroke is one colored line with an absolute timestamp in 120×120 coordinates. PCM is mono signed 16-bit LE, 16kHz, three seconds, 96,000 bytes; network prefetch completes before playback. Wi-Fi power saving is disabled for this candidate; connection timeout is 3s, subsequent header/body reads are 500ms, and temporary body-read EAGAIN retains received bytes within the 15s overall deadline. These are recorded experiment inputs, not product network policy. Full bounded prefetch latency is deliberately visible and may need a future streaming comparison.

Proposed bounds: one concurrent media owner, 16 queued immutable commands, two page requests, 4096 segments, 64 raster segments per worker update, 100ms presentation publication, three 28,800-byte RGB565 copies (86,400 bytes), 96,000 audio bytes, 40,968 sketch bytes, no media cache. Next media allocation would be 96,000 bytes plus a 32,768-byte PSRAM reserve; internal reserve 16,384 bytes plus next 8,192-byte task stack. These are provisional declarations, not measured safe budgets. Network buffers and codec/DMA copies are additional and must be measured. Resource samples report actual heap free/minimum-free/largest blocks, LVGL max-used/largest block, and stack minimum remaining bytes. Heap usage derived from summed regional minima is a conservative upper bound, separately labeled from the observed peak computed from sampled total free space.

Stage-driven scripted path: A play/pause/resume; B focus/play; 20 A/B/A cycles (60 switches); cancel E audio fetch; cancel F sketch fetch; new page while A plays; B play/sign-out; new synthetic lab session with D failure; C audio-only; B pause, move offscreen, resume and return; then 600s alternating A/B playback. This does not implement product login. Each wait has a 25-second stage deadline; cancellation waits for the actual fetch stage and then 40ms, and sustained cycles wait for the prior worker terminal. The terminal drain has a five-second deadline. Review the trace before marking any scenario exercised. The first wall-time candidate missed fetch stages on target; v2 replaces that harness while preserving the exact v1 fixture bytes and service behavior.

## Trace and interpretation

Every `LAB03_TRACE` JSON row has event, monotonic `t_us`, operation ID, generation, session ID, stable message ID, submitted PCM `position_ms`, rendered segment count, and numeric `value`/`aux`. Serial contains no media payload. Host journal retains lifecycle rows; full media trace remains in serial. `trace_loss` reports firmware queue drops; missing or nonzero loss makes results incomplete.

Value/aux meanings: callback/raster/decode/worker_busy events = microseconds / segments (raster only); renderer_backlog = due-unrendered count / oldest due age in ms; reveal_lateness_ms = submitted position minus newly presented stroke due time / stroke due time; internal/PSRAM heap = total free / largest-free bytes; heap_min_free = internal / PSRAM minimum-free bytes; LVGL heap = max used / largest free; worker/ui stack = minimum remaining bytes; allocation = attempts / failures; resident_bytes = raster copies / preallocated audio+sketch bytes. Worker busy time includes codec write blocking and is not CPU utilization. A sparse interval produces no reveal sample. The parser reports first visibility after leaving focus separately from continuous-focus reveal lateness; neither uses an observed DAC clock. `first_frame_ui` and pause UI effect mean invalidation/property update, not confirmed LCD scanout.

`first_codec_write` proves only completed codec submission. Actual first audible sample, DAC position, buffered pause residuals, underrun count/duration and root-cause attribution require acoustic/DMA instrumentation and synchronized screen/audio evidence. The parser intentionally leaves these unknown. Rendering-induced underruns must be separated from the prefetch network-buffering intervals. No performance PASS is possible with these missing observations.
