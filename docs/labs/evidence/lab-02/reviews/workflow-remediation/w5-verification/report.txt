Findings:
1. `scripts/lab02_scenarios.py`: `action()` captures active snap id before HTTP, holds coordinator lock while HTTP runs. Reader remains live via `dispatch_action`; if snap_end is ingested during request, `_recent_events` stores it. When receipt returns, `action()` loops recent events and `_emit_effect_if_ready()` synthesizes scenario_effect from snap_end identity plus action receipt. It does not observe a post-action inbox revision applied by firmware. The callback path repeats this logic if receipt arrived first. This violates proof of action during the same snap / effect application. For S-push, unchanged viewed ID at snap end is not enough to show push was received/applied; for removal, nearest identity may be recorded before changed revision reaches the device.
2. `S-page-snap`: server returns page_receipt_id and server monotonic start/complete timestamps, but firmware only parses/logs receipt id and offset at HTTP response read. It drops server times and does not log run id or snap id on page_fetch. `parse_trace` then has no receipt-to-server-run or fetch-to-device-worker completion identity. `_paired_page` permits absent page snap_id and merely checks trace ordering within any matching snap interval. It picks the first snap_end matching snap id. Classification accepts any truthy action_receipt, including mismatched run/action and `ok=False`. Demonstrated false PASS above. Stale trace from previous run also cannot be excluded because device trace has no run identity.
3. `S-push`/`S-rm-focus` classifier uses synthesized event keyed to action_id but does not validate action receipt run_id/ok itself; it relies on post_action wrapper. Host helper accepts arbitrary receipt in classifier. Reported scenario_effect is host synthesis, not device event. `snap_end` gives identity but no snapshot/revision proving updated server state was applied.
4. Boundedness/ownership: ManagedLab02Server.post_action serializes requests, enforces configured action deadline, returns one terminal server action event, and validates HTTP status, ok, run_id, action_id. The coordinator's separate daemon action thread keeps the serial reader available and rejects overlap. However the coordinator exposes no close/cancel/join contract for that worker; it can outlive the caller/run until request deadline. No host scenario coordinator integration is found in scripts/lab_host.py yet (W7 canonical wiring is later work).
5. Active animation harness remains: `harness_step` calls `lab02_carousel_set_focus(..., true)`, `harness_wait_snap` pumps and awaits scroll_lock false with finite 1.5s bound, then dwell 700ms/500ms. It does not add a scenario-specific pause/focus control. LVGL callback/render path has no newly added sleep; delays are in harness task. No S-push or S-rm controller semantics were introduced in inspected C diffs.
6. Nominal/unmeasured classification: classify_scenario returns INCOMPLETE whenever no action receipt exists before checking scenario name, so nominal/no-action cannot cleanly be UNMEASURED through this API. For unknown scenario with a truthy receipt it returns UNMEASURED. Workflow host receipt success and experiment verdict remain separate in ScenarioResult, but run() currently maps accepted HTTP request to workflow PASS without capture-finalization/evidence/cleanup context, so not a whole-run verdict.

Required proof to close W5: action receipt must be run/action-bound; capture request/receipt ordering and device snap identity with comparable timestamps or explicit handshake; observe applied inbox revision/message identities after action; classify missing/stale/mismatched evidence INCOMPLETE and observed semantic mismatch FAIL; page receipt must carry run/correlation identity and be paired to actual worker completion during that exact snap. Keep host transport receipt success separate from firmware effect failure. Add cleanup/cancellation/join for dispatch worker if it belongs to accepted operation lifecycle.

Ladder/boundary: host/server tests are L1/L2 scripted runtime for host mechanisms; native/IDF build in fixer record is L0; no physical kit or device effect proof (L3). W5's server owner identity, fixture digest receipt, idempotent action keys, action serialization, bounded requests, foreign-port refusal and cleanup behavior have implementation plus focused tests, but these do not repair the proof gaps above.
