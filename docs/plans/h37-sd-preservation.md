## Purpose and limits

H35 detected an SDMMC card. The sanitized [H35 retry summary](../evidence/attached-storage-qualification/h35-preflight-retry-20261005/summary.md) records 121,503,744 sectors × 512 bytes (62,209,916,928 bytes), 4-bit bus at 20 MHz, and zero initialization, deinitialization, and power-off errors. This establishes transport detection only. Filesystem metadata/content have not been inspected, and no attached backend is qualified.

Stage A performs read-only metadata/filesystem classification before any mount, format, or write. The owner has authorized this identified card as disposable experiment media and waived backup/restoration of prior microSD contents. This is not evidence that the card is forensically blank. Following Stage A, separately reviewed bounded filesystem, write, fault, and capacity tests may proceed under exact card/partition limits. Full-card imaging and the former transfer pilot are not prerequisites or on the critical path.

The stages remain gated and ordered. Complete, independently review, and commit Stage A's sanitized evidence and per-epoch BOX restoration proof before mutation. A failed or partial stage stops the sequence. Classification does not silently authorize writes; those still require the exact reviewed manifest and evidence gates below.

## Frozen H37 v1 classification protocol and read ledger

This candidate protocol must be independently reviewed and committed before classification implementation. Every H37 line/record, host request, response, read-ledger entry, and terminal record carries the new immutable `epoch` and `elf_sha256` equal to the runtime ELF SHA-256 from the app descriptor. The parser binds that runtime value to the private build manifest containing source/configuration/app identities; public ledger entries repeat only permitted build/epoch identifiers. The successful H35 reference epoch is metadata in the private H37 manifest only; it is not an H37 epoch or reused authority. H37 schema/version is `H37,1`.

### Frozen H37 v1 wire contract (candidate for independent source review)

Use the global fields `epoch` (the new immutable H37 epoch) and `elf_sha256` (runtime ELF SHA-256, exactly 64 lowercase hex characters) on every firmware record and every host command/ledger entry. Freeze the firmware event set to `BOOT(reset_reason)`, `TRANSPORT(profile,backend,mode,console,usb_host,slot,width_requested,max_freq_khz,command_timeout_ms,byte_budget,max_request_sectors,command_line_max,record_max,session_ms,command_ms,idle_ms,discovery_ms,usb_rx_bytes,usb_tx_bytes)`, `POWER(gpio,active_level,error)`, `HOST(error)`, `SLOT(error)`, `CARD(error)`, `GEOMETRY(sectors,sector_bytes,capacity_bytes,bus_width,real_freq_khz,ddr)`, `CID_PRIVATE(mfg_id,oem_id,revision,serial,date,name_size,name_hex)`, `READY(accepts=BIND)`, `IDENTITY_MATCH(reference_epoch,match,error)`, `READ_RESULT(seq,lba,count,charged_total,error,elapsed_us,len,sha256,b64)`, `CLEANUP(host_deinit_attempted,deinit_error,power_off_attempted,power_off_error)`, and exactly one final `COMPLETE(result,failure_stage,error,read_count,charged_total,bound,scope,media_writes)`. The exact `TRANSPORT` values are `profile=sdmmc_metadata_v1`, `backend=sdmmc`, `mode=read_only`, `console=usb_serial_jtag`, `usb_host=disabled`, `slot=0`, `width_requested=4`, `max_freq_khz=20000`, `command_timeout_ms=1000`, `byte_budget=131072`, `max_request_sectors=8`, `command_line_max=256`, `record_max=8192`, `session_ms=240000`, `command_ms=5000`, `idle_ms=15000`, `discovery_ms=45000`, `usb_rx_bytes=512`, and `usb_tx_bytes=8192`. Keep closed enumerations: `failure_stage=none|resources|reset|power|host|slot|card|geometry|bind|command|read|timeout|cleanup`, plus literal `profile`, `backend`, `mode`, `console`, and `usb_host` values above. Booleans are `0` or `1`; driver errors are numeric integers. Candidate serial line/pin details require source review and remain performance-unverified. Require `scope=classification_only` and `media_writes=0` in every complete terminal record. A firmware counter alone does not prove zero writes; independently review the control flow and APIs to establish that no media-write operation is reachable.

Host commands are positional ASCII, at most 256 bytes including newline: `H37C,1,BIND,<epoch32>,<elf64>,<H35refepoch32>,<privateexpectedCIDdigest64>`; `H37C,1,READ,<epoch32>,<elf64>,<seq>,<lba>,<count>`; and `H37C,1,FINISH,<epoch32>,<elf64>,<nextseq>`. `BIND` is accepted once, only after `READY`; firmware freshly reads/decodes CID, canonicalizes the exact H35 reference digest, and matches it before any `READ`. Read commands are stop-and-wait, `seq` starts at 1 and increments exactly, `count` is 1–8 sectors. Reject malformed/extra fields, wrong bindings, duplicate BIND, unexpected commands, sequence gaps, arithmetic overflow, and out-of-bounds reads. There are no automatic retries; a read error terminates the attempt. `FINISH` is accepted only with the next expected sequence and after every result is complete.

`CID_PRIVATE` uses decimal uint32 values for `mfg_id`, `oem_id`, `revision`, `serial`, and `date`; `name_size` is at most 16 and `name_hex` is exactly twice that many hex characters. Keep this record and all CID-derived material private. Every successful `READ_RESULT` has `len=count*512`, exact sector bytes in base64, and a matching SHA-256; errors require `len=0`, `sha256=none`, and `b64=none`. Charge every dispatched read, including any repeat or uncertain completion, against the 128-KiB limit. Host rejects duplicates, unsolicited/out-of-order responses, mismatched ledger fields, malformed lengths/hashes, and any total above the cap.

Candidate serial buffers are fixed: RX 512 bytes and TX 8,192 bytes, with a 257-byte command-line buffer, a 4,096-byte internal DMA sector-read buffer, and base64 response payload at most 5,464 bytes. Use the native USB Serial/JTAG driver's sole consumer with nonblocking `read_bytes(..., timeout=0)`; install the driver and call `usb_serial_jtag_vfs_use_driver()` before use. Verify this against pinned source and effective configuration before build; these are candidate limits, not measured transport behavior. Firmware terminal `COMPLETE.result` is only `read_complete` or `failed`. For `read_complete`, require `failure_stage=none`, `error=0`, `bound=1`, `scope=classification_only`, `media_writes=0`, and all cleanup attempted/error fields to be `1/0` as applicable. For `failed`, require a nonzero error matching a non-`none` closed failure stage; it produces no filesystem verdict. The host separately derives `classified`, `unknown`, `corrupt`, `unsupported`, or `failed` from the private raw bytes and validated ledger; firmware cannot assert a filesystem verdict. `COMPLETE` must be final and include the actual failure stage/error on failure. No missing or partial terminal can be interpreted as success.

After `READY(accepts=BIND)`, the host sends the single `BIND` command containing the separate H35 reference epoch and its private expected identity SHA-256. H37 recomputes the reference digest from the fresh decoded CID and refuses reads unless the hashes match; only a private `IDENTITY_MATCH` success arms the reader. The host sends stop-and-wait `READ` requests with strictly increasing unique `seq`, `lba`, and sector `count`. Sequence numbers must increase exactly, but LBAs may decrease and the same LBA/count may recur when the validated plan calls for it (for example, backup GPT followed by a partition boot record). Each request is at most 4,096 bytes/eight 512-byte sectors; reject the run without reads if fresh geometry reports another sector size. Firmware independently validates sequence, current card geometry, LBA/count arithmetic and bounds, identity-match state, and cumulative budget before calling the sector-read API. Total dispatched/requested bytes are capped at 128 KiB, including repeats and any request whose completion is uncertain. There are **no automatic sector-read retries**: any SD read error, timeout, identity mismatch, or protocol failure stops classification and emits a complete failure terminal; a subsequent attempt requires a new reviewed immutable epoch. Repeated or unsolicited sequence numbers are rejected; the host charges every dispatched request to the cap even when firmware rejects it. No read command is sent before the private H35 identity match is confirmed by host and firmware.

Candidate `H37,1` records and fields are enumerated in the frozen wire contract above. Every firmware line has `epoch=<new H37 epoch>` and `elf_sha256=<runtime ELF SHA-256>`; host requests and host ledger rows carry the same bindings. A private `READ_RESULT` carries `seq`, `lba`, `count`, exact `len`, sector SHA-256, and base64 raw bytes; each raw record is at most 8,192 bytes and the entire raw capture at most 1 MiB. Raw data/ledger records remain private. The host stores sector bytes in a private epoch-bound snapshot file.

The host validates its dynamic extent table before execution and writes a private H37 READ-plan file bound to the new epoch/build. For every dispatched read, ledger exact requested/returned bytes, sequence, LBA, count, result/error, duration, and cap charge. Independent source/link review must prove the firmware has no media-write path reachable in this fixture; the terminal reports `media_writes=0` as supporting evidence, not as sole proof. Host validation rejects wrong H37 epoch/build/reference, identity mismatch, duplicate/out-of-order sequence, unsolicited data, truncation/oversize, out-of-bounds extents, unexpected gaps or overlaps versus the explicit read plan, length/checksum mismatch, missing read results, any SD read error, failed zero-write source review, excess budget, or malformed terminal order. Repeated LBA/count reads are valid only when separately present in the validated plan. Host READ-plan tables contain only validated dynamic extents and enforce the same total cap.

The device emits exactly one final `COMPLETE` with `read_complete` or `failed` after cleanup and all read results. The host derives `classified`, `unknown`, `corrupt`, `unsupported`, or `failed` from private sector bytes and the validated read ledger; a detected transport without a completed classification remains an incomplete/failed attempt, not a filesystem verdict. A host verdict additionally requires complete ledger, identity match, reviewed zero-write control flow, restored-device proof when flashed, and strict parsing. No premature `COMPLETE` or partial record set can produce a classification verdict.

Candidate execution ceilings for source review are: 5 seconds per READ command/response, 15 seconds output-stall timeout, 45 seconds for transport/card discovery, 240 seconds total for classification, 90 minutes wall time for any complete flash/restore operation, 8,192 bytes per raw record, and 1 MiB per raw capture. These are proposed limits, not measured performance claims; verify them against pinned sources and controller behavior before build, adjusting and reviewing the plan first if necessary.

Public sanitized evidence may contain H37 epoch/build binding, geometry, exact read counts/coverage and timings, classification class, terminal status, and high-level integrity/error counts. Keep raw sectors/base64, per-sector/CID/device-image hashes, private H35 identity digest, private IDs/paths out of public evidence. ## Stage A — Bounded metadata classification

Read no more than **128 KiB total**, inclusive of every dispatched read/repeat. The host constructs an allowlisted dynamic read plan from a sector-aligned MBR, primary GPT header and checksummed array, backup GPT header and checksummed array, and candidate partition boot-record headers needed for signature classification. Permit at most 128 GPT entries of exactly 128 bytes each; reject other shapes, malformed bounds, or checksum failures. Validate backup GPT locations and reciprocal metadata. Exclude extended-partition chains, filesystem content, directory/name data, and arbitrary reads. Each request is at most eight sectors/4 KiB.

Do not mount/probe a filesystem or invoke `fsck`, repair, initialization, formatting, allocation, directory enumeration, filename/path reads, or any write-capable API. Stage A firmware has no Wi-Fi or NVS initialization/write path and preserves the USB Serial/JTAG console. Any SD read error stops immediately with terminal `failed`; no automatic retry. A fresh reviewed epoch is required after failure.

Stage A public evidence may report sanitized geometry, validated partition boundaries, recognized signature classes, exact coverage/count/timing totals, integrity outcome, and `filesystem_contents=not_inspected`. Sector/CID/device-image digests and raw bytes stay private. The strict host parser requires a complete ordered ledger and terminal record and rejects duplicate/out-of-order/truncated records, missing reads, out-of-bounds extents, and premature completion.

After Stage A, restore and independently verify the BOX-3 if flashed, validate parser output and source-reviewed zero-write evidence, obtain independent raw-to-sanitized/privacy review, and commit the Stage A evidence before mutation. The owner's use authority is established for this identified card; Stage A still must establish usable metadata and exact target bounds. Do not advance merely because the card was detected or metadata parsed successfully.
