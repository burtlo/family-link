The reviewed design handles optional trim requests in the custom `ff_diskio` glue by returning `RES_PARERR` before any backend call. ### MBR bytes and exact mutation boundary

The canonical 512-byte sector is zero initialized, has signature bytes `55 AA` at offsets 510–511, one non-bootable partition entry at 446, and three zeroed entries. The sole entry has status `0`, start CHS `FE FF FF`, type `0x0C`, end CHS `FE FF FF`, little-endian start LBA 32768, and little-endian sector count 1,048,576. The MBR disk signature at offsets 440–443 is the little-endian byte encoding of the `uint32` parsed from the first eight hex digits of the H38 epoch. The partition ends exclusively at LBA 1,081,344.

Before its one write, `LAYOUT` revalidates the bound card and old MBR expected hash, confirms the H38 layout manifest, checks all arithmetic against the full geometry, and refuses a previously written layout state. It performs exactly one 512-byte write at physical LBA 0 and reads back that sector. `LAYOUT_RESULT` carries the full readback as private base64 plus its SHA-256; host-side private validation decodes and compares all 512 bytes to the canonical expected MBR. Firmware has no arbitrary raw-write request path.

The `FORMAT` command runs `f_mkfs`, then performs the initial mount and BPB validation; its 4 MiB write/16 MiB read/120-second budgets aggregate format plus that initial mount. It registers only the custom `ff_diskio` mapped wrapper. Its logical sector 0 maps to physical LBA 32768, and it reports exactly 1,048,576 sectors. It calls `f_mkfs` with `FM_FAT32 | FM_SFD`, two FATs, alignment 1 sector, and allocation unit 4,096 bytes, using a 4 KiB work buffer. `FM_SFD` on this virtual disk prevents MBR creation; do not map to an existing MBR partition index, call `f_fdisk`, or register the stock full-card SDMMC disk driver. The wrapper validates the fixed bounds and phase for every read/write/ioctl and 64-bit arithmetic, accepts valid FatFs request sizes within the volume, and splits them into physical driver calls of at most eight sectors using the DMA bounce buffer. It charges every sub-call to the byte/sector budgets before dispatch. Its `CTRL_TRIM` case increments an intercepted-request counter and returns `RES_PARERR` without calling any backend. Its `CTRL_SYNC` result records only API-level success; no card-cache flush is claimed. Source review before build must show no stock registration or unbounded raw physical write path; linker-map/final-ELF review after build and before flash must show no reachable stock SDMMC registration, `sdmmc_erase_sectors`, or raw physical write path except the fixed MBR writer.

### Exact limits and test matrix

- Each accepted virtual-disk callback is range-checked and charged in full, then split into SDMMC driver calls of at most 8 sectors (4,096 bytes) through one 4 KiB internal DMA-aligned bounce buffer. A valid 9-sector callback must complete as 8+1 sectors; any attempted single driver dispatch over 8 sectors fails before dispatch. A one-file transaction has a 30,000 ms post-return ceiling. `command_timeout_ms=1000` is an SD command timeout, not a whole-call guarantee.
- Layout: exactly one 512-byte write to physical LBA 0; no other raw physical writes.
- Format plus initial mount: at most 4,194,304 format-phase write bytes and 16,777,216 read bytes; host format wall cap 120,000 ms. Source calculation predicts `4 + 2*1025 + 8 = 2062` written sectors (1,055,744 bytes) for `f_mkfs`; 4 MiB provides bounded margin. The 4 KiB working buffer is RAM. A source/mock harness must confirm the exact footprint before build.
- I/O phase: cumulative callback reads at most 67,108,864 bytes, writes at most 33,554,432 bytes, and elapsed host-observed wall time at most 900,000 ms. One logical file is at most 196,608 bytes; cumulative generated logical file bytes are at most 33,554,432 bytes; retained logical files, including marker and semantics fixtures but excluding FAT metadata, are at most 2,097,152 bytes. The H32 matrix writes exactly 5,242,880 payload bytes; its six retained payload files total 786,432 bytes, plus at most one 196,608-byte in-flight file and bounded marker/semantics margin.
- Complete capture/session wall cap is 1,200,000 ms; full flash/restore controller wall cap is 5,400,000 ms. These are host stop ceilings, not firmware promises that a synchronous SD call can be interrupted. If an operation has not returned, preserve partial capture and do not claim a terminal, clean cleanup, or unmount. The authoritative host timeout may then invoke only the emergency reset-to-loader path above so BOX restoration can proceed; the card operation remains failed/incomplete and receives no format or repair attempt.
- Reuse the exact H32 two-case contract from `firmware/demos/h32_onchip_storage.c` lines 482–497: 20 iterations each at 65,536 and 196,608 payload bytes; seed is `0x100000 + bytes + iteration`; retain indices 0, 10, 19 for each size. This is 5 MiB total payload writes and 768 KiB retained payload. Preserve its deterministic byte generator, operation ordering/timing, verification, and post-remount checks; do not substitute guessed tests or claim cadence.
- Include the existing H32 POSIX replacement-existing-target fixture (destination remains valid and source remains present when `rename(3)` fails with `EEXIST`), directory enumeration, owned stale `.part` handling, reclamation, and five clean unmount/remount probe checks. These are filesystem/API semantics only. No cadence, 90-cycle fault matrix, physical near-full fill, physical removal, switched-power test, or outbox/production qualification is in H38.

Every counter includes every accepted virtual callback and each resulting SDMMC sub-call, including metadata, verification, repeats, and uncertain completions. Before beginning a virtual callback, validate its entire range and charge its entire byte count against the phase budget; if it would exceed a budget, reject that callback before dispatching any sub-call. Each dispatched driver sub-call is separately checked against the eight-sector maximum. `COMPLETE.read_bytes` and `write_bytes` are whole-run totals; `format_*` and `io_*` fields are phase subtotals. The one physical MBR sector is included in whole-run totals and separately charged to its single-write allowance. Host manifest/parser and firmware wrapper independently enforce the same limits. A hardware failure after one or more sub-calls of an accepted callback is uncertain partial I/O and fails the run; never widen a limit unattended.

### Intercepted-trim accounting

`trim_requests` counts optional FatFs trim requests intercepted by the custom adapter, including requests generated by format and file deletion. Nonzero intercepted counts are expected with pinned `FF_USE_TRIM=1`; they are not backend trim/erase operations. ### Counter units and raw-read allowance

`MOUNT_RESULT.total_bytes` is usable FAT data-cluster capacity (`130811 * 4096 = 535801856` bytes), matching H32 filesystem-space sampling, rather than the partition size. All free-space samples are 4,096-byte multiples within that usable capacity. `IO_RESULT.total_bytes` instead counts payload I/O (`payload_write_bytes + payload_read_bytes`); successful matrix entries report twice their file size. `MOUNT_RESULT.read_bytes`/`write_bytes` are callback-byte deltas during that mount operation, including its info/BPB validation, and are a subset of the corresponding phase counter rather than additional independent byte charges.

The raw LBA-0 reader has a separate fixed allowance of three one-sector attempts (at most 1,536 bytes): BIND old-MBR verification, LAYOUT old-MBR revalidation, and LAYOUT readback. Charge attempts before dispatch, including failed/uncertain attempts; no raw retry or arbitrary LBA exists. Whole-run read bytes include these raw reads plus accepted FORMAT/IO virtual callbacks, with an absolute ceiling of `16777216 + 67108864 + 1536 = 83887616` bytes. The one allowed physical MBR write is likewise charged before dispatch. Sector-transfer byte counters exclude card initialization/status register commands; phase wall times still include synchronous work.
